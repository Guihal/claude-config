# Менеджмент поведенческих правил-инъекций

Это НЕ про `.agents/skills/inject-rules` (тот — про manifest браузерного расширения). Это про
систему `~/.claude/mcp/injection-rules/`, которая на каждом ходу впечатывает своды поведения
(`[00-whole-before-parts]`, `[01-a-working-product]`, …) через хуки Claude Code.

## Главное: правила сходят с образа, а не сочиняются

Единственный источник поведения — **образ идеального агента** `~/.claude/docs/ideal-agent.md`.
Это картина (проза), из которой правило — проекция на исполняемую процедуру. Цепочка:

```text
ideal-agent.md (картина, «каким быть»)
    └─ rules/NN-name.json (проекция → процедура + STOP-условия, инжектится в контекст)
        └─ роль-промпты ~/.claude/agents/*.md (та же процедура, суженная под роль)
```

Отсюда порядок при новом поведении (сверху вниз, как велит сам образ §0):

1. **Сперва правь образ.** Нет поведения в картине — правило будет сиротой без основания. Каждое
   правило несёт поле `_derives: "ideal-agent.md → <раздел>"`; это не украшение, а проверяемая
   ссылка. При конфликте правила с картиной прав образ, правило переписывается.
2. **Потом проецируй в правило** `rules/NN-name.json`.
3. **Роль-специфичную процедуру** клади в роль-промпт, не в always-on инъекцию (см. blast-radius).

## Анатомия правила `rules/NN-name.json`

```json
{
  "name": "NN-kebab-name",
  "apply": ["*", "!role-to-exclude"],
  "_tier": "T1|T2",
  "_derives": "ideal-agent.md → <раздел, из которого спроецировано>",
  "body": "[NN-name] КАПС-ЗАГОЛОВОК ОДНОЙ МЫСЛЬЮ.\nПлотная процедура: триггер → операция → STOP.\nГРАНИЦА С MM-...: где кончается это правило и начинается соседнее.",
  "remind": { "every_n_turns": 21, "suffix": "\n\n[NN-name] Сжатый рефрен на каденции." },
  "_comment": "verbatim-цитата запроса юзера + вывод из образа + карта границ + дата."
}
```

- `name` — `NN-kebab`, где `NN` кодирует band (см. нумерацию). Дедуп идёт **по `name`**: два файла
  с одним `name` → второй молча отбрасывается.
- `apply` — массив. `"*"` = все роли (wildcard). `"!role"` = исключить роль. Без wildcard нужен хоть
  один позитивный include, иначе правило невалидно (`apply-no-positive`).
- `body` — то, что инжектится всегда (на своей каденции). `remind.suffix` — короткий рефрен,
  подмешиваемый раз в `every_n_turns` ходов (тик = сообщение юзера ИЛИ тул-колл).
- `_comment` — дисциплина: **verbatim-цитата** запроса юзера (чтобы потом видеть исходную волю),
  **вывод из образа** (какой раздел спроецирован), **карта границ** с соседними правилами, дата.

## Нумерация (band)

| Диапазон | Тема |
|----------|------|
| 00–0x | подход/altitude, рабочий продукт, проверка (00, 01, 02, 03, 04) |
| 10–1x | честность/чтение/советник (10, 11, 12, 13, 14, 15, 16) |
| 20–2x | инварианты/простота/пространство решений/высота (20…27) |
| 30–3x | безопасность и необратимое (30, 31) |
| 40 | внешние факты |
| 50–5x | процесс: задачи, делегирование, цель, стоп (50, 51, 52, 53) |
| 60–6x | инструментальное: вёрстка, гит, правки (60, 61, 62) |

Новое правило — в band по смыслу, свободный `NN`. Band задаёт и грубый порядок инъекции.

## Как отбирается и инжектится

- `rules/` грузится `loadRules()` с **process-local кешем** `_rulesCache`. Хуки —
  короткоживущие процессы (каждый вызов = свежий `node`/`bun`), поэтому **новый/правленый файл
  правила они видят сразу, без рестарта**. А демон MCP живёт долго и кеширует — его инструменты
  `list_rules/get_rule/status` показывают старое **до рестарта демона**. ⇒ проверять правку
  свежим прогоном хука, а не `list_rules`.
- Тик каденции: `injection-rules-userprompt.mjs` (на сообщение юзера) и
  `injection-rules-posttooluse.mjs` (на КАЖДЫЙ тул-колл). Оба зовут `evaluate()` и отдают тела
  подходящих правил, упакованные под `CHAR_BUDGET`.
- Спавн сабагента доставляет роль-набор один раз (`subagentRules` по `apply`); у сабагента свой
  `session_id`, свой стейт-файл, своя каденция.

## Бюджет и каденция

- `CHAR_BUDGET_DEFAULT` в `core.mjs` — пол+рекомендация, не тиски; каталог спроектирован расти под
  контент. Добавил тело → подними потолок под рекомендацию.
- Инструменты: `tools/budget-sim.mjs --horizon 2000` (симуляция нагрузки на N ходов),
  `tools/cadence-search.mjs` (перераспределение `every_n_turns`, если тесно по пику).
- Правило может быть «только в рефренах» (opt-out из основного бюджета) — см. `makeRule`.

## Как писать тело: процедура, не лозунг

Модель (в т.ч. Opus) абстрактную установку («думай системно», «будь внимателен») не исполняет —
превращает в ритуальную болтовню, а при перегрузе начинает дрочить сами мета-правила. Исполняется
конкретная **операция**. Поэтому:

- Кодируй **процедуру смены уровня + STOP-условия**: `триггер → операция → критерий остановки`,
  а не декларацию. Держи **4–6 жёстких эвристик**, не 50 пунктов чеклиста.
- Острые операционализируемые приёмы: **semantic-stop** (уточнять семантику слова только когда
  разночтение меняет поведение/гарантии/границы/архитектуру), **counterfactual-rename-test**
  (рассуждение рассыпалось после переименования сущностей → оно на словах, а не на системе).
- **Проводи границу с соседними правилами прямо в теле** (`ГРАНИЦА С MM-…: …`). Буквальный
  читатель застревает между двумя правилами (напр. «предложи лучший путь» 13 vs «не делай сверх
  запроса» 15), пока граница не проведена в тексте одного из них.

### Запретительная формулировка работает хуже позитивной

LLM плохо следуют негативным инструкциям («не делай X»): чтобы понять запрет, модель сначала
активирует сам концепт X (эффект «розового слона» / ironic process theory), и вероятность
всплытия X растёт. Позитивные инструкции («делай Y») исполняются надёжнее — меньше двусмысленности.
Отсюда:

- Формулируй **как правильную процедуру к исполнению**, а не как список запретов.
- Где запрет необходим — **паруй его с позитивной заменой**: не «не молчи», а «предложи словом»;
  не «не подгоняй оракул», а «красное чинит код». Голое «не делай X» слабее, чем «делай Y вместо X».
- Каталог уже так устроен (13: «не молчи „раз просили так“» → «предложи СЛОВОМ и жди решения»).

(Проверено поиском: Pink Elephant / ironic process theory; рекомендация reframe negative→positive —
устойчивый результат prompt-engineering.)

## Blast-radius: инъекция vs роль-промпт

- **Always-on `*` инъекция** — глобальные принципы, нужные всем ролям (`00` глобальный принцип,
  `20` инварианты, `16` самокритика). Едят бюджет каждого хода каждой сессии — клади только то,
  что верно везде.
- **Роль-промпт `~/.claude/agents/*.md`** — операциональные линзы под конкретную роль; бюджет
  инъекций не едят. `planner`: L0→L2 до файлов. `worker`: инварианты апстрима как authoritative.
  `critic`: линзы local-patch-vs-systemic / special-case-vs-general / impl-promoted-to-requirement.
- Семантика уместна на уровне worker (спека authoritative), системность — на архитектурном
  (planner/critic).

## Enforce харнессом, а не громким текстом

Ключевой урок: **константный текст-напоминание на каждом ходу декодируется вниманием как фон**
(баннерная слепота) и перестаёт исполняться. «То же, но громче» — не фикс. Правильно —
**условный сигнал, пропорциональный реальному разрыву**: молчит при соответствии, бьёт резко при
нарушении. Пример в репо — `~/.claude/hooks/_task-gap.mjs`: читает стор задач
(`~/.claude/tasks/session-<первые8 session_id>/*.json`), считает тул-коллы, и выдаёт строку ТОЛЬКО
когда список задач реально отстал (0 задач при ≥K тул-коллах; нет in_progress; in_progress висит
>N мин). Врезан наверх блока в обоих хуках; сам-Task*-тул пропускается, чтобы не бить по ведению
списка. Паттерн переносимый: **состояние → предикат разрыва → редкая резкая строка**.

## Добавить/поменять правило — процедура

1. **Образ**: убедись, что поведение есть в `ideal-agent.md`; нет — впиши прозой (propose-first,
   это самый несущий файл — покажи юзеру перед правкой live).
2. **Правило**: создай `rules/NN-name.json` по анатомии. Тело — процедурой, позитивно, с границами;
   `_comment` с verbatim-цитатой и деривацией; `_derives` на реальный раздел образа.
3. **Бюджет**: `node tools/budget-sim.mjs --horizon 2000` → подними потолок под рекомендацию;
   тесно по пику — `tools/cadence-search.mjs` раскидает каденции.
4. **Проверка (обязательна, это правило хука — гоняй свежим процессом)**:
   ```bash
   echo '{"session_id":"probe1234","prompt":"hi"}' | node ~/.claude/hooks/injection-rules-userprompt.mjs
   ```
   Тело нового правила должно появиться в `additionalContext`. `list_rules` демона может показывать
   старое до рестарта — не полагайся на него.
5. **Коммит**: `~/.claude` под git — коммить осмысленной порцией с причиной.

## Gotchas

- **Дедуп по `name`**: два файла с одинаковым `name` → второй молча теряется. Имя уникально.
- **Демон кеширует, хуки — нет**: правку видно в хуках сразу, в MCP-инструментах — после рестарта
  демона.
- **Стейт-файлы пишутся атомарно уникальным tmp** (`state.<id>.<pid>.<rand>.json.tmp` → rename).
  Читатель толерантен к битому JSON (свежее состояние + stderr), чтобы гонка записи двух хуков не
  роняла Stop-хук. Не возвращай общий tmp — вернётся интерливинг и битый стейт.
- **Нативная напоминалка Claude Code ≠ эта система**: константное «Первое действие после сообщения
  юзера — обнови список задач…» инжектит сам Claude Code, переписать его нельзя; рычаг — только
  хуки injection-rules.
- **Волатильный факт (версия, путь, дата) в тело правила НЕ пишется** — протухнет молча. Место
  факта — память `~/.claude/memory/`. В образ и правила идёт только durable «как быть».

## Связанные артефакты

- `~/.claude/docs/ideal-agent.md` — образ, источник.
- `~/.claude/mcp/injection-rules/core.mjs` — движок (loadRules, evaluate, state I/O, бюджет).
- `~/.claude/mcp/injection-rules/rules/*.json` — сами правила.
- `~/.claude/hooks/injection-rules-{userprompt,posttooluse,stop,sessionstart,subagentstart,postcompact}.mjs`
  — точки инъекции; `_ir-helper.mjs` — обёртка emit; `_task-gap.mjs` — пример state-aware нуджа.
- `~/.claude/memory/encode-behavior-as-procedure-not-slogan.md` — исходная памятка по форме правил.
