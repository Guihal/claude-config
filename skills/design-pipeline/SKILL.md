# design-pipeline — от мешанины скринов до исполненных пакетов

Оркестратор. Контракты фаз живут в скиллах фаз — здесь только маршрут, гейты
и порядок. На каждом шаге: прочитать скилл шага, выполнить, убедиться что
выходной файл существует, идти дальше.

## Принцип

**Скрины = структура, код-выгрузка = значения.** Каждая фаза — файл на выходе,
он же вход следующей. Любая фаза перезапускаема отдельно; слаги блоков
стабильны сквозь весь пайплайн.

## Маршрут

| # | шаг | скилл | вход → выход |
|---|-----|-------|--------------|
| 0 | приём входа | — | design-папка → инвентарь |
| 1 | карта блоков | `design-block-map` | скрины → `block-map.<page>.md` + `shared.block-map.md` |
| 2 | карта стилей | `design-style-map` | код-выгрузка + карта → `style-map.<page>.md` |
| 3 | UI-черновик | `design-tz-draft` (+`ui-standards`) | обе карты → `tz-draft.<page>.md` |
| 4 | привязка к проекту | `design-project-bind` | черновик + репо → `tz.<page>.md` |
| 5 | нарезка | `design-tz-split` | tz → `tasks.<page>.md` |
| 6 | пакеты | `tz` | таск → пакет-ТЗ (по одному) |
| 7 | исполнение | `task` | разблокированный пакет → код |
| 8 | сверка (опц.) | `design-conformance` | живой URL + tz → `conformance.<page>.md` |

## Шаги

**0. Приём входа.** Инвентарь design-папки: скрины (обязательны — без них
СТОП, структуру взять неоткуда), код-выгрузка (желательна; нет → фаза 2
вырождена, в style-map явно фиксируется `source: NONE`, значения будут
`MISSING` — не выдумывать со скринов). Определить имя страницы и design-корень
проекта (для shared.block-map.md).

**1–3. Универсальные фазы.** Строго по скиллам `design-block-map` →
`design-style-map` → `design-tz-draft`. Не перескакивать: фаза 3 без фазы 2
даст ТЗ без значений. `ui-standards` фаза 3 читает сама (references только
задействованных элементов).

**4. Привязка к проекту** — `design-project-bind`. ⛔ **Human-гейт:** секция
`## Conflicts` в tz.md непуста → показать юзеру варианты, ждать решения. Не
решать молча.

**5. Нарезка** — `design-tz-split` → `tasks.<page>.md` (deps, параллельность,
acceptance).

**6. Пакеты через `tz`.** Для каждого таска из tasks.md (по порядку deps):
сырьё для `tz` = секция таска + ссылки на соответствующие секции `tz.<page>.md`.
`tz` оформляет полный пакет-ТЗ и ведёт gap-механику. ⛔ **Human-гейт (из
скилла tz):** пакет блокирован, пока gap не пуст и нет явного сигнала старта —
соблюдать полностью, не обходить.

**7. Исполнение через `task`.** Каждый разблокированный пакет →
«via task» (`task`), **без указания модели** — здесь всё требует
максимальной верификации, критик-гейты обязательны. Порядок — deps из
tasks.md; помеченные `[parallel]` секции можно вести параллельно. Пакет с
архитектурной неопределённостью → `task --depth=complex` (3 ревьюера) вместо
task. Для новых визуальных секций при исполнении уместен
`frontend-design`.

Цикл 6→7 повторяется по таскам до конца tasks.md (финальный интеграционный
таск — последним, после него пайплайн закрыт).

**8. Сверка (опционально)** — после интеграционного таска прогнать
`design-conformance` (живой URL × tz.md → расхождения по слагам). Report-only;
расхождения → точечные фикс-таски через цикл 6→7. Уместна на прод/staging после
деплоя.

**Мобайл после desktop-only.** Если tz-draft дал `responsive: UNSPECIFIED`, а
позже понадобился адаптив → `responsive-derive` (⛔ human-гейт: derived-план
юзеру до пакетов). На первом проходе UNSPECIFIED — забота фазы 3, не отдельный
вызов.

## Resume

Пайплайн возобновляем: по наличию артефактов в design-папке определить
последнюю завершённую фазу (block-map → style-map → tz-draft → tz → tasks) и
войти со следующей. Артефакт есть, но вход изменился (новые скрины/выгрузка) →
перезапустить его фазу, слаги сохранять.

**v2 макета ПОСЛЕ готового tz.md** — не полный перепрогон, а `design-diff`:
классифицирует слаги (added/removed/changed/unchanged) и патчит точечно только
затронутые. Изменение входа в процессе фаз 1–5 (tz ещё нет) — по правилу выше
(перезапуск фазы).

## Жёсткие правила

- Не перескакивать фазы и не сливать их выходы в один файл.
- Не дублировать контракты фаз здесь — источник правды всегда скилл фазы.
- Human-гейты (Conflicts, tz-gap) не обходить и не «принимать за юзера».
- Массовая волна пакетов по многим страницам → рассмотреть `operator`
  (packet-wave оркестрация) вместо ручного цикла 6→7.
