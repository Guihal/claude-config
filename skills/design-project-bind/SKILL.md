# design-project-bind — черновик × репо → финальное ТЗ

Фаза 4 цепочки (после `design-tz-draft`). Всё проектное — здесь и только
здесь: фазы 1–3 переносимы между проектами, эта — нет.

## Вход

- `tz-draft.<page>.md` (контракт — скилл `design-tz-draft`).
- Текущий репозиторий (cwd).

## Шаг 1 — discovery репо

Прочитать: корневые `AGENTS.md`/`CLAUDE.md`/`README` (+ вложенные у
frontend-пака), карты токенов и переменных (искать: scss maps/vars, tailwind
config, css custom properties, design-tokens файлы), каталог компонентов /
template-parts / ui-kit, существующие утилиты (слайдер, попап, форма).
Зафиксировать в `## Repo profile` (стек, токен-источник, где компоненты,
binding-механизм контента: CMS-поля / props / i18n / API).

## Шаг 2 — токен-матч

Каждое raw-значение из ТЗ → таблица:

| raw | вердикт |
|---|---|
| `#F4EEE7` | токен `c(cream)` |
| `14/18.2 #626262` | ≈ существующий text-стиль X (расхождение указать) |
| `#B08D57` | **NEW** → предложить имя токена |

Правила: точный матч > «похожий» (расхождение фиксировать явно, решает
человек); NEW-значения собрать отдельным списком «добавить в токены»; то же
для компонентов: блок ТЗ ↔ существующий компонент/класс (реюз/модификатор) или
NEW.

## Шаг 3 — data-binding

Каждый `[data]`-атом → источник:

- существующий (поле CMS, коллекция, проп, файл переводов) — указать точно;
- **NEW SOURCE** — дескриптор-рекомендация: `{name, type
  (text/richtext/image/list/relation), cardinality, editable-by-client: Y/N,
  default}`. **Схему НЕ проектировать** (группы полей, миграции — отдельный
  data-layer таск в `design-tz-split`, risk-tier: schema).

Хардкод текстов в шаблонах — дефолтно запрещён, если правила проекта не
говорят иного.

## Шаг 4 — rules-check

ТЗ против правил проекта (нейминг, нестинг, структура файлов, запреты).
Конфликт дизайна с правилом → секция `## Conflicts` с вариантами решения —
НЕ решать молча.

## Выход, формат + пример

`<design-dir>/tz.<page>.md` — самодостаточный (имплементатор НЕ читает draft):

```markdown
# TZ: factory
## Repo profile
стек: …; токены: …; компоненты: …; данные: …

## hero
- hero.lead — реюз text-стиля `.lead` (расхождение: lh 18.2 vs 18 — принять
  токен проекта). Контент ← поле `factory_description` (existing).
- hero.media — реюз слайдер-утилиты проекта, конфиг: 4+ слайдов, dots.
  Слайды ← галерея `image_gallery` (existing).

## NEW tokens
- (список | пусто)
## NEW sources
- factory_kicker {text, 1, editable: Y, default: ""}
## Conflicts
- (список с вариантами | пусто)
```
