# CSS Architecture — организация стилей

Про то, КАК устроены стили в целом, а не про конкретные элементы (те — в
`ui-standards`). Правила ниже — дефолт; проектные правила (CLAUDE.md/AGENTS.md,
basa/agents.md) сильнее при конфликте.

## Законы

1. **Слои токенов: primitive → semantic → component.** `--gray-900` (primitive)
   → `--color-text` (semantic, ссылается на primitive) → компонент читает
   только semantic. Компонент не хардкодит primitive и тем более литерал.
2. **Нестинг — стандарт.** Селекторы пишутся вложенно (`.parent { &__child {} }`),
   не плоско. Одна ремарка про специфичность: нативный CSS-nesting оборачивает
   вложенное в `:is()`, что **поднимает специфичность** до самого весомого
   селектора в списке — не вкладывать без нужды глубоко и не мешать
   ID-селекторы в общий список.
3. **Section-gap модель: вертикальным ритмом владеет секция/layout, НЕ контент.**
   Отступы между секциями задаёт секция (`--section-gap`), а не `margin` у
   заголовков/параграфов внутри. Один источник ритма — иначе двойные отступы и
   «кто кого перебьёт». Контент-элементы внутри — flow-spacing (`> * + *`), не
   личные margin'ы наружу.
4. **Modifier vs новый класс — порог.** Меняются только токены/значения (цвет,
   размер, паддинг) при той же анатомии → **modifier** (`.card--accent`). Меняется
   структура/состав → **новый класс/компонент**. Не плодить `.card-2`, не лепить
   5 булевых модификаторов там, где нужен отдельный компонент.
5. **Бюджет специфичности.** Без ID-селекторов в стайлинге; без `!important`
   вне utility-слоя; глубина вложенности ≤3. Растёт война специфичности →
   архитектура сломалась, а не «добавь ещё !important».
6. **Границы utility vs component.** Utility — одна декларация, презентационное,
   переиспользуемое (`.mt-4`, `.sr-only`). Component — именованный блок с
   поведением/состояниями. Не строить компонент из 15 utility в разметке там,
   где нужен semantic-класс; не делать utility со сложной логикой.
7. **Файловая организация — по компонентам/секциям.** Один
   компонент/секция = один файл. Токены — отдельно (карты/переменные). Не
   сваливать в один мега-файл, не размазывать один компонент по трём.

## Антипаттерны

- Литерал цвета/размера в компоненте вместо semantic-токена.
- Плоские `.block__el__sub` вместо вложенности.
- `margin-top` у заголовка ради отступа секции (ломает section-gap модель).
- `!important` для перебивки собственной специфичности.
- Глубина `.a .b .c .d .e` — рефакторить, не углублять.

## Когда отступать

Проектный дизайн-ток/методология (BEM-строго, Tailwind-utility-first,
CSS-in-JS) задаёт свои границы — следовать репо. Legacy-слой с ID-селекторами
не переписывать ради чистоты, если не просили — co-exist, новое писать по
законам.
