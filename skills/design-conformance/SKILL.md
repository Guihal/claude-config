# design-conformance — страница × ТЗ → расхождения

Замыкает петлю: не «дизайн → код», а «код (живой) → сверка с ТЗ». Выход — сырьё
для фикс-тасков. **Скилл НЕ правит вёрстку** — только отчёт.

## Вход

- URL страницы (локальный прод или staging — тот, где вёрстка задеплоена).
- `tz.<page>.md` — основной источник ожиданий (слаги + значения). Нет tz →
  fallback на `style-map.<page>.md` + `block-map.<page>.md` (слаги + raw-значения).
- **Фиксированный viewport width** — берётся из `breakpoint:` карты блоков
  (напр. 1440). Проверка идёт ровно на этой ширине; другой viewport = другой
  контракт, не смешивать.

## Инструмент

Браузерные тулзы сессии (snapshot структуры + computed styles через evaluate).
Скилл говорит ЧТО проверять, не хардкодит имена MCP-тулзов — использовать те,
что доступны в текущей сессии (Playwright и т.п.).

## Проверки по слагу

Для каждого слага из block-map:

- **present/absent** — блок найден в DOM (по структуре/тексту/роли).
- **computed vs ТЗ** — ключевые значения (размеры шрифта, цвета, отступы,
  раскладка) через `getComputedStyle`. Допуски — **по acceptance-языку
  `design-tz-split`** (не выводить заново):
  - округление ±1px;
  - цвет — нормализация в rgb перед сравнением (`#1F1F1F` == `rgb(31,31,31)`);
  - шрифт — сравнивать **первый доступный шрифт стека**, не фактически
    отрендеренный (fallback-подмена ≠ расхождение ТЗ).
- **псевдоэлементы** — `getComputedStyle(el, '::before')` / `'::after'`, если
  ТЗ описывает их (иконки, декор-линии).
- **wait-for-stable** — перед снапшотом дождаться, пока transition/animation
  завершатся; замер в процессе анимации = ложный DIVERGENT.
- **данные не хардкод** — если ТЗ указывает источник данных, на странице должен
  быть реальный контент, не lorem/placeholder.
- **states** — hover/focus проверяемы best-effort (навести/сфокусировать,
  перечитать computed). Непроверяемые в браузере — `UNCHECKABLE`.

## Выход, формат + пример

`<design-dir>/conformance.<page>.md` — таблица по слагам + сводка:

```markdown
# conformance: factory · 2026-07-22 · viewport 1440

| slug | verdict | деталь |
|---|---|---|
| hero.media | OK | — |
| hero.title | DIVERGENT | ожидалось font-size 48px, фактически 42px |
| hero.kicker | DIVERGENT | ожидалось color rgb(98,98,98), факт rgb(31,31,31) |
| bestsellers.slider | OK | 4 слайда, dots активны |
| bestsellers.slider.card.badge | MISSING | блок не найден в DOM |
| contacts.form.submit | UNCHECKABLE | hover-состояние не воспроизвелось |

Сводка: OK 3 · DIVERGENT 2 · MISSING 1 · UNCHECKABLE 1.
Расхождения → фикс-таски (не правятся здесь).
```

Verdict-грамматика: `OK` | `DIVERGENT (ожидалось X, факт Y)` | `MISSING` |
`UNCHECKABLE(причина)`.

## Далее

Расхождения — вход для точечных фикс-тасков (через `tz` → `task`).
Слаги в отчёте те же, что в block-map — фикс адресуется по слагу.
