# Animation Standards — переходы и анимации

Дефолт хорошего motion. Проектные правила сильнее при конфликте.

## Законы

1. **Шкала длительностей:**
   - micro (hover, focus, мелкие тоглы): **100–150ms**;
   - standard (дропдауны, аккордеоны, модалки): **200–300ms**;
   - large (страничные/крупные перемещения, оверлеи): **400–600ms**.
   Дольше 600ms для UI-микровзаимодействия — воспринимается как лаг.
2. **Easing-токены, не линейно:**
   - вход/появление — `ease-out` (быстрый старт, мягкая посадка);
   - уход/исчезновение — `ease-in`;
   - перемещение A→B — `ease-in-out`.
   Линейный easing — только для непрерывного (спиннер, прогресс).
3. **Анимировать только `transform` и `opacity`.** Они на compositor'е, не
   вызывают reflow/repaint. `width/height/top/left/margin` в анимации → дёрганье
   → замена на `transform: translate/scale`.
4. **Запрет `transition: all`.** Перечислять свойства явно
   (`transition: opacity .2s, transform .2s`) — иначе анимируется лишнее,
   включая дорогие layout-свойства, и ломается при добавлении новых.
5. **`prefers-reduced-motion: reduce` — обязателен.** Под ним убирать/сводить к
   мгновенному крупные и параллакс-движения (оставлять максимум opacity-фейд).
   Не игнорировать — это a11y, не опция.
6. **Hover-переход симметричен.** Одна длительность/easing на въезд и выезд
   hover — иначе «залипание». Разнести in/out можно осознанно (напр. быстрый
   выезд, медленный въезд), не случайно.
7. **Entrance-анимации — один раз.** Появление секции при скролле проигрывать
   единожды, не на каждый re-enter вьюпорта. Stagger соседних элементов —
   малый шаг (≤50–80ms), не «волной на секунду».

## Про `will-change`

`will-change: transform` ставить **точечно и временно** (перед/на время
анимации), не держать постоянно на многих элементах — каждый создаёт слой
компоновки и жрёт память, эффект обнуляется. Часто вообще не нужен.

## Антипаттерны

- `transition: all .3s` на интерактивном элементе.
- Анимация `height`/`margin` вместо `transform`.
- Длительность 800ms+ на hover/дропдаун.
- Нет `prefers-reduced-motion`.
- Постоянный `will-change` на десятках элементов.

## Когда отступать

Брендовый motion-гайд проекта задаёт свои кривые/тайминги — следовать ему.
Декоративная сцена (лендинг-hero, промо) может выходить за UI-шкалу осознанно,
но `prefers-reduced-motion` всё равно обязателен.
