`ListAgents` в Claude Code (сборка на 2026-08-19) возвращает `No reachable agents`, когда роли
живы и продолжают писать. Замерено дважды за одну сессию: тул отдавал «пусто», а `planner-d2`
после этого зарегистрировал ещё две ревизии плана; второй раз — критик работал, а тул снова
показал пусто (оператор подтвердил: «он работает, опять клод-код сломался»).

**Why:** я дважды принял пустой ответ за смерть роли. Первый раз запустил второго планировщика
поверх живого первого — вышла гонка писателей на одном файле (спасло то, что второй заметил рост
файла между двумя `stat` и спросил, вместо того чтобы мержить). Второй раз чуть не заспавнил
второго критика.

**How to apply:** признак живости и завершения роли брать ИЗ АРТЕФАКТА, а не из тула — ровно так,
как предписывает контракт `task`/`task-lite`: гейт пройден, когда `VERDICT_FILE` существует и
парсится, а не когда агент «закончил». Работает ли роль прямо сейчас — судить по росту файла между
двумя `stat -c '%s %y'` с паузой, либо по `pgrep -af harness-agent` для отвязанных процессов
(у in-process субагентов тула `Agent` своего процесса нет вовсе). Пустой `ListAgents` не
доказывает НИЧЕГО и не является основанием спавнить дубль роли.

Связано: [[subagent-dies-on-session-restart]] — там причина обратная (роль реально умирает с
сессией), поэтому два признака нельзя путать.
