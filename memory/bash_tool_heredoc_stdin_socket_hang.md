**Факт (проверено 2026-09-04 командой, не догадка).** В Bash-туле Claude Code stdin шелла зависит от текста команды:

- команда **без heredoc** → `readlink /proc/$$/fd/0` = `/dev/null`, `timeout 3 cat` выходит сразу с кодом 0;
- команда **с heredoc** (`cat > file <<'EOF' … EOF`) → stdin = `socket:[…]`, который никто не закрывает: `timeout 5 cat` висит и умирает по таймауту (exit 124).

Любой дочерний процесс, который читает stdin, когда он не TTY, наследует этот сокет и ждёт EOF вечно. Так висли три запуска `pi -p …` (18:03Z, 19:41Z, 19:49Z): расширения загружались, `session_start` не наступал, stdout пустой, exit 124 по таймауту. Все три команды содержали heredoc перед `pi`; все рабочие запуски были без heredoc. Ни один плагин pi при этом не виноват — гипотеза «плагин не даёт завершиться» не подтвердилась.

**Why:** юзер: «да есть проблема с stdin … это ваша постоянная проблема». Симптом выглядит как зависание продукта, и на него уходят часы диагностики плагинов, локов и гонок, хотя причина — среда тула.

**How to apply:**

- Дочерние интерактивные/агентские процессы из Bash-тула запускать **всегда** с явным `< /dev/null` (`pi -p … < /dev/null`, `codex …`, `claude -p …`, любые CLI, умеющие читать промпт из pipe).
- Heredoc (запись файла) и запуск процесса — **разные вызовы тула**; файлы лучше писать тулом Write, а не `cat <<EOF`.
- Диагностика «команда висит без вывода, ничего не логирует после старта» начинается с `readlink /proc/$$/fd/0`, а не с плагинов.
- Записано также в `~/.pi/agent/AGENTS.md` (раздел про запуск pi из другого агента).
