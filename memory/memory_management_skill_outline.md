Скилл управления встроенной памятью Claude Code. Поставлен юзером 2026-08-22 отдельной задачей
через таск-цикл, ПОСЛЕ пересборки правил и CLAUDE.md. Повод: «она превращается в мусорку ебаную».

**Очертания (не финальная спека — рамка, из которой выводится скилл):**

- *Что становится фактом памяти.* Только то, что добыто трудом и не выводится заново: грабли
  отладки, решения юзера с их «почему», внешние ограничения. НЕ идёт в память: то, что читается
  из кода/гита/конфига за секунду, и то, что живёт только внутри текущей задачи.
- *Один факт — один файл.* Новый факт по уже существующей теме — правка того файла, а не второй
  рядом. Перед записью — поиск дубля по теме, не по имени.
- *Индекс — не витрина, а вход.* `MEMORY.md` автоинжектится целиком в начале сессии (первые ~200
  строк / 25KB), сами файлы приходят по релевантности. Значит: строка на файл, буквально одна,
  и каждый файл в индексе. Расхождение «файлов больше, чем строк» = факт невидим.
- *Протухание.* Факт о состоянии системы стареет молча и потом уводит агента в несуществующее
  (кейс `subbrain`: строка в конфиге про несуществующий MCP). Нужен способ отличать вечное
  (решение юзера, принцип) от датированного (версия, путь, состояние сервиса) и правило
  перепроверки перед использованием.
- *Кто пишет.* Память не делегируется воркеру — её пишет главный агент.
- *Чего НЕ делать.* Не строить это как гейт с порогами и счётчиками — юзер такое прямо запретил
  ([[abstract_level_first]], [[effort_matches_stakes]]). Скилл описывает смысл и решение, а не
  метрику чистоты.
