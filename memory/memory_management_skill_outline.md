Скилл управления встроенной памятью Claude Code **сделан** — `~/.claude/skills/memory-curation/`
(`SKILL.md` + `references/how-memory-loads.md`). Поставлен юзером 2026-08-22 отдельной задачей
через таск-цикл, ПОСЛЕ пересборки правил и CLAUDE.md. Повод: «она превращается в мусорку ебаную».
Открывать скилл перед любой правкой памяти; механику носителя (пути инжекции, pinned, регулярка
ссылок индекса) держит reference и перепроверяет командами прямо в бинаре.

**Очертания (рамка, из которой выведен скилл):**

- *Что становится фактом памяти.* Только то, что добыто трудом и не выводится заново: грабли
  отладки, решения юзера с их «почему», внешние ограничения. НЕ идёт в память: то, что читается
  из кода/гита/конфига за секунду, и то, что живёт только внутри текущей задачи.
- *Один факт — один файл.* Новый факт по уже существующей теме — правка того файла, а не второй
  рядом. Перед записью — поиск дубля по теме, не по имени.
- *Индекс — не витрина, а вход.* Память приезжает одним из двух путей (см. reference скилла):
  либо `MEMORY.md` целиком, либо собранный CLI индекс из frontmatter файлов. Значит: строка на
  файл, буквально одна, и каждый файл в индексе. Расхождение
  «файлов больше, чем строк» = факт невидим. Границы объёма индекса зашиты в бинарь константами
  и читаются командой (см. reference), снимком тут не хранятся.
- *Протухание.* Факт о состоянии системы стареет молча и потом уводит агента в несуществующее
  (кейс `subbrain`: строка в конфиге про несуществующий MCP). Датированный факт (версия, путь,
  состояние сервиса) хранится как команда перепроверки, а не как снимок-ответ; вечное (решение
  юзера, принцип) — как есть.
- *Кто пишет.* Память не делегируется воркеру — её пишет главный агент.
- *Чего НЕ делать.* Не строить это как гейт с порогами и счётчиками — юзер такое прямо запретил
  ([[abstract_level_first]], [[effort_matches_stakes]]). Скилл описывает смысл и решение, а не
  метрику чистоты.
