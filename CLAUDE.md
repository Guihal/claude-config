# Global rules (guihal) — Claude Code specific

@AGENTS.md — cross-tool baseline. Этот файл — CC-специфичные дополнения **поверх**, без дублей.

## Task-тулы — где живут задачи

`TaskCreate`/`TaskGet`/`TaskUpdate`/`TaskList` **включены** через `env.CLAUDE_CODE_ENABLE_TODO_TOOLS=1`
в `~/.claude/settings.json` (2026-08-19). Тулы в бинарнике были всегда, но `isEnabled` для моделей
`opus ≥ 4.8` / `sonnet 5` / `fable 5` уходит на statsig-гейт `tengu_rosy_wren` (по умолчанию
выключен) — именно поэтому на opus-5 их не было, а на opus 4.x были бы. Env-переменная гейт обходит.

**Задачи держим тулами, не в этом файле.** Список лежит в `~/.claude/tasks/session-<id>/<n>.json`:
переживает компакт и `--resume`, но привязан к сессии — новая сессия стартует пустой. Восстановление
в новой сессии: `TaskList` пуст → перечитать кристалл (`~/.claude/tasks/--<cwd>--/YYYY-MM-DD/<стем>.md`)
и план (`~/plans/<стем>.md`) живой задачи и завести список оттуда. Durable источник — кристалл и план,
не `CLAUDE.md`.

Дисциплина: закрыл — в тот же ход `TaskUpdate status=completed`, и **чем подтверждено** (команда +
вывод, хеш ревизии, вердикт) — в `description`. Не заводить задачу на пробу или итерацию, только на
то, что переживает компакт.

## ⚠️ НИКОГДА НЕ СПРАШИВАЙ, ЕСЛИ МОЖЕШЬ СДЕЛАТЬ САМ (CRITICAL)

Юзер дал задачу → **сделай сам, проверь сам, почини сломанное сам, выдай финал**.

- НЕ проси "покажи X" / "запусти Y" / "подтверди Z" — если можешь Read/Bash/tool'ом.
- НЕ "сделать или ты хочешь по-другому?" — если намерение считывается.
- НЕ "тут несколько вариантов, какой выбрать?" — если один очевиден.
- НЕ "проверь у себя" / "посмотри сам" — делай и проверяй сам.
- НЕ "скажи, продолжать?" — продолжай до финала.

**Loop на задачу:** сделать → проверить (test/build/typecheck/lint) → починить сломанное → повторить до зелёного → финал.

`AskUserQuestion` / clarifying question — **только** когда:
- Намерение реально нечитаемо (не «удобно спросить», а буквально 2+ равновероятных интерпретации).
- Действие hard-to-reverse / destructive / security / out-of-scope (rm -rf, force-push, prod deploy, schema migration) и нет approval.
- Внешняя система без tool-доступа (скриншот, ручной тест, external API без credentials).

**Никогда** не спрашивай то, что tool даст за секунду. Тупик (нет доступа / hard-to-reverse) — один короткий вопрос. Иначе — тишина и работа.

## ⚠️ INTENT-FIRST. READ THE USER, NOT THE WORDS. (CRITICAL — non-negotiable)

Юзер — СДВГшник. Пишет свободно, с опечатками, резко, телеграфно. **Буквальное следование = провал.** Читай намерение, не слова.

1. **Считывай намерение через контекст.** Свободный формат + опечатки + резкость = «он имеет в виду X, потому что это ложится в задачу».
2. **Лучше спросить один раз, чем угадать три.** Не считываешь — `AskUserQuestion` коротко (в рамках правила выше). Считываешь — делай.
3. **Сначала `Read`/`Bash`/тест, потом утверждение.** «Может сломаться», «вероятно упадёт», «теоретически» без проверки = деза. Юзер знает свой код лучше.
4. **Сделал не то — скажи прямо:** «моя ошибка, понял так: [что]». Не доказывай, не подкручивай, не делай вид что так и было.
5. **Говори прямо**, если видишь сломанный путь. Не подыгрывай.

Примеры (сессия tatishevpark):
- «убери нахуй из бандла `<!DOCTYPE>...<body>`» → intent: **вся обвязка**, не только DOCTYPE.
- «собери в один скрипт» → intent: **один main.js от одного entry**, а не склейка двух inline-скриптов.
- «оно должно быть инлайново» → intent: **никаких внешних `<script src=>`**, всё inline в одном HTML.

## Caveman ru

Скилл `caveman` — английский и общий; эти правила — ru-специфичная надстройка, не дубль. Применять **только когда caveman явно запрошен или речь про внутреннее** (промпты субагентам, коммиты, заметки): на объяснениях юзеру caveman запрещён, см. AGENTS.md § Caveman mode.

- Дроп частиц: `же`, `бы`, `ли`, `ведь`, `вот`, `уж`, `просто`, `именно`.
- Дроп ясных местоимений: `я`, `ты`, `он/она/оно`, `это`. `я думаю надо X` → `надо X`.
- Дроп связок: `является`, `представляет собой`, `имеет место`.
- Дроп вспомогательных: `был/была/было` когда время понятно. `будет сделано` → `сделаю` / `TODO`.
- Инфинитив/императив > спряжения: `нужно добавить` → `добавить`.
- Сокращения: `т.е.`, `т.к.`, `напр.`, `см.`, `ок`. Короткие синонимы: `необходимо`→`надо`, `использовать`→`юзать`, `выполнить/осуществить`→`сделать`.
- Стрелки: `X приводит к Y` → `X → Y`. Дроп предлогов где ясно: `в файле src/foo.ts` → `src/foo.ts`, `на строке 42` → `:42`.
- Фрагменты ok: `Проверил. Баг в sanitizeFtsQuery. Фиксить завтра.`
- Code/paths/commands/versions/dates — **не сокращать**. Security/destructive confirms → полные фразы.

## Behavioral rules

Требования к коду (простота, архитектура, функции, именование, ошибки, эффекты, комментарии) — § «Код — обязательные требования» в конце файла.

### Surgical changes
- Не «improve» соседний код/комментарии/формат. Не рефакторить не-сломанное. Match existing style.
- Убирать импорты/переменные, которые осиротели **от моих** правок. Pre-existing dead code — не трогать, упомянуть.
- Каждая изменённая строка трассируется к запросу юзера.
- Исключение (сильнее правила): **любой баг, который ВОСПРОИЗВОДИТСЯ** (есть команда/тест/сценарий) — чинить сразу, в том же диффе, где бы он ни лежал: другой модуль, чужой код, секция «out of scope» в плане. **Out-of-scope как причина не чинить не существует.** Не выносить за скобки, не прятать в TODO, не переносить «на следующую задачу». Назвать отдельной строкой отчёта: что было, где, чем чинил, чем воспроизводится. Не воспроизвёл — это гипотеза, а не баг: назвать в отчёте, не трогать. Единственное исключение: фикс требует risk-tier действия (миграция, prod, security, destructive) — сначала подтверждение.

### Goal-driven execution
Определить success → крутить до verified. «Add validation» → «тесты на невалидный вход, потом зелено». «Fix bug» → «тест, воспроизводящий баг, потом зелено». Multi-step → короткий план `1. шаг → verify: чек`.

### Look it up yourself
Можно прочитать/проверить самому (file, git status, diff, output) — **читай, не проси «покажи»**. «покажи single.scss» → `Read`. «покажи diff» → `git diff`. «что там» → `Read`/`Bash`. «коммить» → коммить, не «покажи сначала».

## ⚠️ «ЧЕРЕЗ TASK» — прочесть скилл и следовать построчно

«через таск» / «via task» / «используя task» → **обязательно** `Skill skill="task"` (либо `task --depth=complex`, если явно нужен multi-reviewer plan-loop), прочесть целиком, следовать построчно. Не «я знаю что там» — скиллы меняются.

Non-negotiable из `task`: главная сессия — **оператор**, а не писатель. План пишет роль `planner`, код — роль `worker`, приёмку даёт `verifier`; оператор владеет кристаллом, диспетчем, гейтами и решениями, своей рукой правит только кристалл и пишет записи журнала. Гейт `critic` обязателен на плане и (full mode) на реализации.

Роли запускаются **отвязанным процессом ОС**, а не тулом `Agent`: `~/harness-lib/bin/harness-agent <role> <prompt-file> --log <log> [--new <verdict>] [--perm narrow|bypass]`. Причина измерена: субагент живёт внутри процесса Claude Code и умирает вместе с сессией — 2026-08-17 рестарт сессии убил три раунда гейта подряд, вердикты не были написаны вообще. `Agent(subagent_type:)` — только для короткой роли, которая точно уложится в сессию.

Делегирую `task` субагенту — через скилл `dispatch-task-subagent`, не голым промптом: у уже заспавненного Agent гейт молча пропускается (промпт Agent-тула «не спавнить без явной просьбы»), и RLM-цикл теряется. Дело не в капе (`CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH`, дефолт 3, main=0 → критик со дна субагента разрешён).

## Делегация

Дополнение к делегации в AGENTS.md.

- `TeamCreate` **больше нет** — у сессии одна неявная команда, `team_name` у `Agent` deprecated/ignored. Оркестрация = `Agent` (уходит в фон, возвращается уведомлением) + `TaskCreate`/`TaskUpdate` для трекинга + `SendMessage`/`ListAgents` для связи с живыми агентами + `ScheduleWakeup` для heartbeat.
- Именуй агента (`name`) при спавне — тогда его можно догнать `SendMessage` вместо перезапуска с нуля.
- `subagent_type: "fork"` наследует мой контекст; любой другой — стартует холодным и переоткрывает то, что я уже знаю. Холодный спавн = дорогой путь, не спавнить ради «многогранности».

Пороги автоматического решения:
- Identical subagent (description+prompt) ≥2 раза за 5 мин → STOP, переосмыслить подход.
- Параллельные independent-таски → несколько именованных `Agent` + `TaskCreate` на трекинг, один writer на файл.

**Verify after delegate.** Субагент сказал «done», changes ≥ ordinary tier: `git diff` (реальный diff vs описание агента) + узкий тест. Summary агента = что он *хотел*, не обязательно что *сделал*.

## GitHub CLI (gh) — несколько аккаунтов

Снапшот на 2026-08-19: `gh auth status` держит два аккаунта на `github.com` —
`Guihal` (основной) и `WebAppLabPlatform` (второй, добавлен 2026-08-19), у
обоих scope `admin:public_key`. Переключение `gh`-команд (`gh pr create`,
`gh issue`, `gh api` и т.п.) между ними — `gh auth switch --hostname
github.com --user <name>`.

Push/pull по SSH от `gh auth switch` **не зависит** — резолвится по хосту в
remote URL, у каждого аккаунта свой ключ:
- `Guihal` — дефолтный ключ, обычный `git@github.com:owner/repo.git`.
- `WebAppLabPlatform` — отдельный ключ `~/.ssh/id_ed25519_webapplab` + алиас
  `github.com-webapplab` в `~/.ssh/config`. Репозитории этого аккаунта
  клонировать/пушить через `git@github.com-webapplab:owner/repo.git`
  (`git remote set-url origin ...` для уже склонированных).

Причина отдельного ключа: GitHub не даёт привязать один и тот же публичный
ключ к двум аккаунтам («key is already in use»).

Самопроверка: `ssh -T git@github.com-webapplab` → `Hi WebAppLabPlatform!`;
`ssh -T git@github.com` → `Hi Guihal!`.

## Код — обязательные требования

Заменяет выпиленные правила инъекции (`code-architecture`, `code-functions`, `code-naming`, `code-error-handling`, `code-side-effects`, `code-no-spaghetti`, `code-comments`) и ядро плагина `ponytail`. Это требования, не пожелания.

При конфликте с правилом инъекции `a-working-product` побеждает `a-working-product`: простое/одноразовое решение — только по явной просьбе юзера, дефолт — конфиг, а не хардкод, и думай наперёд. Краткость из § Простота — тайбрейк ПРИ РАВНОМ качестве, а не право оставить кривое.

### Простота
Лестница — остановись на первой ступени, которая держит:
1. Нужно ли это вообще? Спекулятивная надобность → НЕ ДЕЛАЙ, скажи одной строкой.
2. Уже есть в репо (хелпер, util, тип, паттерн)? ПЕРЕИСПОЛЬЗУЙ. Переписывать своё то, что лежит парой файлов рядом — главный источник слопа.
3. Stdlib решает? БЕРИ stdlib.
4. Нативная фича платформы? `<input type="date">` вместо пикер-либы, CSS вместо JS, constraint БД вместо кода в приложении.
5. Уже установленная зависимость? БЕРИ её. Новая зависимость ради 10 строк — ЗАПРЕЩЕНО.
6. Влезает в одну строку? ПИШИ одну строку.
7. Только теперь — минимальный работающий код.

- УДАЛЯЙ охотнее, чем добавляй. Скучное > умное: умное разбирают в 3 ночи.
- ДЕРЖИ минимум файлов и самый короткий РАБОТАЮЩИЙ диф — короткий диф не в том месте не считается.
- Запрос выглядит сложным — отдай простую версию И сам поставь вопрос в том же ответе: «сделал X, покрывает Y; нужен полный X — скажи». Не зависай на решении, которое можешь принять по умолчанию.
- ЗАПРЕЩЕНО: интерфейс с одной реализацией, фабрика на один продукт, конфиг под значение, которое никогда не меняется, скаффолдинг «на потом».
- Лестница сокращает РЕШЕНИЕ, не ЧТЕНИЕ: сперва пройди весь путь кода, который правишь, и только потом упрощай. Маленький диф не в том месте — это второй баг, а не экономия.
- Осознанно срезал угол с известным потолком (глобальный лок, O(n²), наивная эвристика) — пометь комментарием `ponytail:` с потолком и путём апгрейда.
- Баг чини В КОРНЕ: перед правкой грепни ВСЕХ вызывающих функцию. Один гард в общей функции — диф меньше, чем гард в каждом вызове, и чинит соседние пути тоже.
- Нетривиальная логика (ветка, цикл, парсер, деньги, безопасность) без чека НЕ СДЕЛАНА: оставь ОДИН запускаемый чек — `assert`-based `demo()`/`__main__` или один `test_*.py`. Тривиальный однострочник тестами не обвешивай.
- НИКОГДА не упрощай: валидацию на границах доверия, обработку ошибок, спасающую данные, безопасность, базовую доступность, явно запрошенное юзером.

### Архитектура
- ДЕРЖИ слои: transport / service / domain / repo / util. Слой = папка с одним направлением зависимостей.
- SRP: модуль = одна причина для изменений. Валидация + IO + логика в одном месте — РАЗНЕСИ.
- Зависимости строго сверху вниз: domain НЕ импортирует transport, утилиты НЕ импортируют домен. Цикл = баг, чини сразу.
- РАЗДЕЛЯЙ concerns: парсинг, валидация, бизнес-правила, persistence, presentation — разные единицы. >1 concern в функции — ВЫНОСИ.
- Публичный API слоя = минимум экспортов, внутреннее приватно.
- YAGNI > DRY: абстракцию тяни только под конкретную существующую проблему.

### Функции
- Pure где возможно: вход → выход, без эффектов и глобалов. Impure — помечай эффект в docstring/JSDoc.
- IO (file, network, db, console, time, random) держи НА ГРАНИЦЕ слоя (handler/adapter/repo). В domain/service — pure.
- ≤40 строк (идеал ≤20). Длиннее — ВЫНОСИ подфункции.
- Параметров ≤3 идеал, ≤5 максимум. Больше — объект с именованными полями. Параметр-флаг — почти всегда баг: разбей на две функции.
- Возврат — явный тип, без `any`/`unknown` без сужения. `null`/`undefined` как признак ошибки ЗАПРЕЩЁН: throw или Result.
- Композиция через pipe/`then`, не вложенность. 3 уровня вложенности — потолок.
- Один уровень абстракции на функцию: парсинг + валидация + маппинг + SQL в одной функции = баг.

### Именование
- Функции — глагол: `parseInput`, `fetchUser`, `validateOrder`. ЗАПРЕЩЕНО `process`/`handle`/`doStuff`/`run` без объекта.
- Предикаты `is*`/`has*`/`can*`/`should*` → boolean: `isAdmin`, `hasPermission`, не `admin`.
- Булевы переменные только `is*`/`has*`/`should*`/`can*`: `active` → `isActive`.
- Коллекции во множественном числе: `users`, `orderItems`. Не `userList`/`userArr`/`userData`.
- Map/Dict — `*ById`/`*ByKey`/`*Map`: `usersById`, не `userMap`.
- В циклах `i`/`j` для индексов, `user`/`item` для элементов. Не `theUser`/`usr`.
- Константы UPPER_SNAKE для enum и magic numbers (`MAX_RETRIES`, `STATUS_ACTIVE`); runtime-конфиг — в env/config, не в коде.
- Файлы kebab-case (`user-service.ts`); PascalCase — только React-компоненты и классы-файлы; snake_case — только Python. Модули kebab-case или short-lowercase.
- Длина имени пропорциональна scope: локальная `i` — ок, публичный аргумент `userId`, глобальный конфиг `MAX_CONCURRENT_CONNECTIONS`.
- ЗАПРЕЩЕНЫ двойные отрицания: `isNotDisabled` → `isEnabled`.

### Ошибки
- Типизируй: класс на домен (`ValidationError`, `NotFoundError`, `AuthError`), иерархия от `DomainError extends Error`.
- ЗАПРЕЩЕНО `throw "msg"` — теряет stack, тип, контекст, не ловится instanceof.
- ЗАПРЕЩЕНО `throw new Error("user not found")` без подкласса — заведи `NotFoundError`.
- ЗАПРЕЩЕНО `catch (e) { return null }` — подавление = тихий баг. Пробрось или обработай: лог + rethrow с `cause`, либо Result.
- Propagation: нижний слой бросает доменную ошибку, верхний ловит, логирует с контекстом и конвертирует в user-facing формат, сохраняя `cause`.
- `Result<T,E>` для ожидаемых отказов (validation, parse, not found); throw — для неожиданных.
- ЗАПРЕЩЕНЫ return-коды: `return -1`/`null`/`false` как признак ошибки.
- Catch-all только на границе системы (entry/main/handler). Внутри слоёв лови только известные типы.
- Логируй `error.stack`, не только `error.message`.

### Side effects
- Side effect = ЛЮБОЕ: IO, network, db, console, mutation, `Date.now()`, `Math.random()`, глобал, throw.
- Pure core / impure shell: impure wrapper → pure core → impure wrapper. Pure core тестируется без моков.
- DI вместо прямых вызовов: параметр `clock`/`fileReader`/`db`, в тестах — fake.
- `Date.now()` нетестируемо: передавай `now: () => number` (prod `systemClock()`, tests `fixedClock(...)`). `Math.random()` — seedable RNG.
- Pure НЕ мутирует аргументы: `arr.sort()` мутирует → `return [...arr].sort()`.
- `console.log` в production — баг, используй logger с уровнями.
- `db`/`cache`/`httpClient` в domain-код напрямую НЕ импортируй — только через DI.
- Собери impure в именованные функции с префиксом эффекта: `readConfig`, `sendEmail`, `commitTransaction`; тестируй их отдельно (integration).

### Антипаттерны — жёсткие запреты
«Это маленький скрипт» не аргумент.
- НЕТ бизнес-логики в entry/main/handler: вход = парсинг + вызов верхнеуровневой функции + exit code.
- НЕТ god-object'ов: знает всё и делает всё — разделяй.
- НЕТ global mutable state: никаких module-level `let cache = {}`, `let currentUser`, `let db`. Состояние — через аргументы или DI.
- НЕТ monkey-patching и мутаций `Object.prototype`/`Function.prototype`: расширяй наследованием или композицией.
- НЕТ copy-paste логики: два места делают одно — выноси.
- НЕТ магических строк и чисел: `status === 3` — баг, `status === STATUS_ACTIVE` — норма.
- НЕТ длинных if/else: 4+ ветки по одному признаку → таблица + lookup.

### Комментарии
- Комментарий объясняет ПОЧЕМУ, а не ЧТО. Пересказ кода — мусор, код читается сам.
- КОММЕНТИРУЙ инварианты, контракты, неочевидные trade-off, предупреждения («не менять порядок полей — сломается сериализация»).
- TODO/FIXME/HACK — только с причиной и ссылкой на issue.
- Docstring обязателен у экспортируемых функций/классов/типов: что делает, параметры, возврат, исключения.
- ЗАПРЕЩЕНО комментировать очевидное — переименуй переменную/функцию.
- ЗАПРЕЩЕНО оставлять врущий комментарий: изменил код — обнови комментарий.
- ЗАПРЕЩЕНО оставлять закомментированный код — удаляй, история в git.
